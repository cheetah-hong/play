# 1차 코드리뷰 요청 (codex · 단일 에이전트 · read-only)

## 실행 제약 — 반드시 지킬 것
- 이 요청은 migrated `/review-pr` 명령이 **아니다**.
- `source-command-review-pr` 등 **다중관점 리뷰 스킬을 호출하지 마라**.
- 서브에이전트를 생성하지 말고 **단일 codex 에이전트**로 수행하라.
- 전체 diff 를 **한 번** 스윕하고, 이후에는 호출부·스키마·설정·CI 계약 및 BLOCKER/MAJOR 후보의
  근거 확인에 필요한 범위만 추가 조회하라. 동일 영역을 관점만 바꿔 **반복 스윕하지 마라**.
- **신뢰도 80% 이상**이며 재현 가능한 결함만 보고하라.
- 테스트 공백은 **실제 회귀가 CI 를 녹색 통과하는 구체적 시나리오**가 있을 때만 보고하라.
- 단, 필요한 **계약 대조와 MAJOR 후보 교차검증은 제한하지 마라**.
- read-only 조회(cat/sed/grep/rg)는 해도 된다. **pytest 등 테스트 실행·쓰기 명령은 하지 마라.**
- 테스트 디렉터리(`src/test/`, `tests/` 등) 아래 파일을 생성·수정·삭제하지 마라.
- git 을 호출할 필요가 없다 — diff 는 아래 절대경로 파일에 있다.

## 대상
- 저장소: `{{REPO_DIR}}`
- 기준: `{{BASE}}` 대비 워킹트리 (HEAD = `{{HEAD}}`, 미커밋·미추적 변경 포함)
- diff: `{{DIFF_FILE}}`
- 변경 파일 목록: `{{FILES_FILE}}`

## CI · 로컬 테스트 결과 (샌드박스가 네트워크를 막으므로 여기 직접 넣는다)
{{CI_RESULT}}

## 전담 영역
전체 diff 스윕 — 의존성 · 설정 · 스키마 · CI · 명세 위반. (보안 공격자 관점·언어 관용구는 다른 리뷰어가 따로 본다)

## 출력 형식
심각도: BLOCKER=즉시 수정(게이트 차단) / MAJOR=당일 수정 / MINOR=이슈 이월

| # | 심각도 | 파일:줄 | 결함 | 재현 시나리오(입력→잘못된 결과) | 신뢰도 |
|---|---|---|---|---|---|

- 지적이 없으면 **"BLOCKER 0 · MAJOR 0 — 지적 없음"** 이라고 명시하라(침묵과 구별되게).
- 마지막 줄에 **기준 커밋(HEAD={{HEAD}})** 과, 다 못 봤다면 무엇을 못 봤는지 적어라.
